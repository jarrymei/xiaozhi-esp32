# LED接线与PWM调光实验记录

记录日期：2026-11-02。对应ESP-IDF v5.5.6、小智v2.2.4、Bread Compact WiFi，以及现有ESP32-S3 N16R8开发板。

本文件保存此前已经完成的单颗外接LED实验，方便拆线后恢复。用户当前准备拆除LED和单颗舵机，转做LCD适配；这里记录的是历史验证接法，不表示LED目前仍连接。软件说明已对照记录当日源码核对。

## 1. 快速恢复接线

| 元件端点 | 连接目标 |
|---|---|
| ESP32的GPIO18 | 限流电阻的一端 |
| 限流电阻的另一端 | LED正极，A（阳极） |
| LED负极，K（阴极） | ESP32 GND |
| 开发板供电 | USB数据线接电脑 |

```text
电脑USB ─────────────→ ESP32-S3开发板

ESP32 GPIO18 ── 限流电阻 ── LED正极 A
                              LED负极 K ── ESP32 GND

电流路径：GPIO18 → 电阻 → LED → GND
```

这是一条串联支路，不需要另外给LED连接5V或3V3。限流电阻放在LED前面或后面都能限流，但本项目统一按图记录，方便复查。不要把GPIO18同时接到5V、3V3或GND。

GPIO18指开发板丝印标注的GPIO编号，不是从板边数第18个针脚。这里控制的是外接LED，不是GPIO48对应的板载灯。

## 2. 所需元件和已知范围

| 物料 | 说明 |
|---|---|
| 普通两脚指示LED | 1颗；实验实物颜色及型号尚未补记 |
| 限流电阻 | 1只；历史实际使用阻值未确认，不能把建议值写成实测值 |
| 面包板和跳线 | 固定LED、电阻和连接开发板 |
| ESP32-S3与USB线 | 提供控制信号和实验供电 |

此前文档建议的起步阻值为1kΩ或470Ω；恢复实验时优先确认原电阻阻值，普通小型指示LED不确定参数时先用1kΩ观察。电阻并非越小越好，不要短接电阻。

本接法仅适用于一颗低电流指示LED，不适用于灯带、大功率LED或照明灯。那些负载需要另行设计驱动与供电。

## 3. 如何辨认LED和面包板孔位

- 未剪脚的新LED通常长脚为正极、短脚为负极；外壳平边通常在负极一侧。剪过脚后不要只凭长短判断，可用万用表二极管挡辅助识别，并以元件资料为准。
- 普通电阻没有正负极。
- LED的两个脚必须插到面包板上互不导通的孔组中，否则可能被孔组直接短接。
- 面包板中间常按每5孔一组连接；两侧电源轨有的中间断开。以实物为准，用断电通断测量确认，不能假设整条都连通。
- 使用公共GND轨时，必须有一根线把该轨连到开发板GND。

## 4. 断电搭建与首次通电

1. 拔掉开发板USB；如其他模块有外部电源，也先断开。
2. 插好电阻与LED，确认是串联关系。
3. 接GPIO18到电阻，接LED负极到GND。
4. 复查LED极性、面包板连通关系，以及是否误接到了5V。
5. 插入USB，运行已有程序。当前代码默认亮度为0，上电后LED不亮是正常行为。
6. 发出“开灯”或“把灯亮度设为百分之十”等指令，并查看实际MCP工具调用日志。
7. 验证亮度变化和关灯功能。若不亮，先按后面的排查表检查，不要直接减小电阻。

换线或调换LED方向时先断电。拆除此支路时，不要误拆麦克风、功放等模块共用的地线。

## 6. PWM调光原理与资源

GPIO用高、低电平快速交替输出，LED也随之快速亮灭。PWM的“占空比”就是每个周期中高电平所占的比例，占比越高，平均发光时间越长。对于本接法，高电平时导通，因此占空比越大通常越亮。

| 参数 | 当前源码值 |
|---|---|
| LEDC模式 | `LEDC_LOW_SPEED_MODE` |
| 定时器 | `LEDC_TIMER_2` |
| 通道 | `LEDC_CHANNEL_2` |
| PWM频率 | 5000Hz，即每秒5000个周期 |
| 周期 | 约200μs |
| 分辨率 | 10位 |
| 占空比计数范围 | 0～1023 |
| 软件亮度范围 | 0～100，整数百分比 |

代码先限制输入在0～100，再计算：

```text
duty = 1023 × percent ÷ 100
```

整数运算会舍去小数。例如10%对应102，50%对应511，100%对应1023。然后调用`ledc_set_duty()`设置计数，再调用`ledc_update_duty()`使它生效。

这里改变的是点亮时间比例，不是把GPIO高电平电压改成某个较低电压；限流电阻仍然必须保留。亮度百分比是软件的线性占空比，不代表人眼感知严格线性。

LED使用5kHz，单颗舵机使用50Hz，二者采用不同LEDC定时器。以后新增屏幕背光或舵机时，不要随意复用并重配定时器2，否则可能改变LED的输出频率。

## 7. 工具名称和状态行为

| MCP工具 | 参数 | 实际行为 |
|---|---|---|
| `self.lamp.get_state` | 无 | 返回软件记录的`power`和`brightness` |
| `self.lamp.turn_on` | 无 | 恢复最近一次非零亮度；启动后尚未设亮度时恢复50% |
| `self.lamp.turn_off` | 无 | 设置为0%，保留最近非零亮度 |
| `self.lamp.set_brightness` | `brightness`，0～100整数 | 设置亮度；0表示关闭 |

状态示例：

```json
{"power":true,"brightness":30}
```

示例调用参数：

```json
{"brightness":30}
```

`brightness_`初始为0，`last_brightness_`初始为50。先设30%、再关灯、再开灯，会恢复30%。这些变量只保存在内存中，重启后恢复初始值。

工具查询的是**软件记录**，没有光传感器测量实际光亮；即使LED拆掉，工具仍可能正常返回“开灯成功”。中文语音如何映射到工具由云端决定，测试时以工具日志为准。

## 8. 日志和定位顺序

```text
[MCP RX]          收到云端工具消息
[TOOL CALL]       工具名称与参数
[TOOL EXEC]       开始执行工具回调
[TOOL RESULT]     回调返回结果
```

若没有`self.lamp.*`的工具调用，先排查语音或工具调用链路；若回调成功但LED没反应，再排查接线、极性、电阻及GPIO。不要把回调返回成功等同于实物已经点亮。

## 9. 常见问题

| 现象 | 优先检查 |
|---|---|
| 上电不亮 | 当前默认就是关闭，先发开灯指令 |
| 调用成功但始终不亮 | LED极性；是否插进同一孔组；GPIO18是否接对；公共GND是否接到开发板 |
| 开灯恢复到50% | 重启后尚未设置非零亮度，这是初始恢复值 |
| 设置10%后很暗 | 电阻值、LED本身和人眼感知；先尝试50%，不要先去掉电阻 |
| 无法调亮或始终亮 | 是否绕过GPIO接到电源；是否改错控制器文件；是否发生LEDC通道/定时器冲突 |
| LED或电阻明显发热 | 断电检查是否缺少限流、阻值错误、供电接错或LED损坏 |

## 10. 拆除及后续恢复

断电后拆除GPIO18到电阻、LED和该支路GND连接即可。不要因LED拆除而删除共享地线。源码仍注册灯光工具并输出PWM，不会因为拔掉LED自动关闭这些功能。

本记录保存接线和实现；本次没有修改或重新编译固件，也没有进行新的实物测试。恢复时先低亮度单支路验证，再与其他设备一起运行。
