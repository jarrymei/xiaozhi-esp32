# LCD双眼表情实验

日期：2026-11-02。基于已经实物点亮的微雪1.69寸240×280 LCD，接线无需修改。

## 显示效果

黑色背景、青色圆角双眼，参考EMO的电子眼风格，使用LVGL图形绘制，不使用EMO原版素材。

| 设备状态 | 双眼表现 |
| --- | --- |
| 待机 | 正常睁眼，视线轻微左右移动 |
| 聆听 | 眼睛睁大，视线回到中央，颜色稍亮 |
| 说话 | 眼睛高度和位置轻微律动 |

首次眨眼约在界面建立1.8秒后，随后每隔约2.8～5.8秒再次眨眼；一次闭眼与睁眼约250毫秒。启动彩条覆盖期间，底下的眼睛动画也会继续计时，因此不一定能看到首次眨眼。

说话动画由设备状态驱动，**没有读取音量，也不是与语音逐字同步**。这版尚未实现眼神跟随摄像头或触摸。

云端下发的 `happy`、`laughing`、`loving` 会让眼睛变扁一些，`sad`、`sleepy` 会让眼睛半睁；`neutral` 恢复正常。其他情绪及系统图标仍调用原来的表情逻辑，下一次待机、聆听或说话状态可恢复双眼。

## 保留的功能

- 顶部网络、电池、静音、设备状态和通知。
- 底部识别文字与回复字幕。
- 原来的图片预览逻辑：预览期间暂时隐藏表情容器。
- BOOT按键、语音对话、LED和舵机控制代码及MCP工具。
- LCD的SPI引脚、10MHz时钟、背光控制及20行显存偏移。
- 保留开机红绿蓝测试层的代码；当前 `DISPLAY_STARTUP_TEST_MS=0`，已关闭启动彩条。

LED和舵机代码保留，不代表拆下的硬件可以直接执行实物动作。恢复接线时查看各自的独立实验文档。

## 代码原理

`main/display/display.h` 增加默认不执行任何操作的 `SetInteractionState(DeviceState)` 接口。`main/application.cc` 在处理实际设备状态变化时调用它，其他显示器不需要修改。

本板的 `robot_eye_display.h` 继承已有LCD测试显示类，继续使用原来的状态栏、字幕和表情容器。每只眼睛是一个带圆角的LVGL矩形，通过改变高度模拟眨眼。状态切换时高度逐步接近目标值，减少突然跳变。

动画使用50毫秒周期的LVGL定时器，名义更新频率20次/秒。只创建一次对象，后续修改尺寸和位置，不在每帧创建图片、任务或对象，也不使用阻塞延时。实际刷新速度取决于SPI传输和系统负载，20次/秒不是实测保证。

外部状态和情绪更新使用显示锁；定时器回调运行在LVGL任务中。图片预览或系统图标隐藏双眼时跳过眼睛绘制。

## 编译与验证

本次已使用ESP-IDF v5.5.6编译通过，生成 `build/xiaozhi.bin`，大小为 `0x28b7a0` 字节，应用分区剩余35%；`git diff --check` 通过。编译仍有视频组件与lwIP的 `_IO`、`_IOR`、`_IOW` 宏重复定义警告，本次未改这些组件。

已核对舵机控制头文件、LED控制头文件、MCP实现和 `sdkconfig` 的SHA256，与本次修改前一致。

在已经配置ESP-IDF v5.5.6的PowerShell终端执行：

```powershell
idf.py build
# 按照原来的方式选择串口并烧录、查看日志
idf.py -p COM你的串口号 flash monitor
```

实物验收顺序：

1. 启动彩条结束后，观察黑底双眼和顶部状态，等待约10秒确认多次眨眼。
2. 唤醒机器人，检查聆听时睁眼变大，并确认识别字幕仍显示。
3. 提一个能让机器人回答几秒的问题，检查说话时双眼律动与回复字幕。
4. 对话结束后检查恢复待机；连续对话几轮，观察是否卡顿、闪屏或出现音频中断。
5. 使用BOOT按键确认原通知仍显示；需要时检查主题切换、图片预览及原控制工具。

### 已确认的实机结果

2026-11-02，用户已烧录，并反馈：“眼睛能正常眨眼，聆听和说话时也能切换表情”。因此，自动眨眼与聆听、说话状态切换已完成第一轮实机验证。

当前效果仍是基础版本，用户认为显示比较简陋，需要继续优化LCD界面。尚未单独确认长时间运行、连续多轮对话的流畅度，以及主题切换、图片预览和所有云端情绪的兼容情况；不能据此标记为全部验收完成。

## 下次继续：LCD显示优化

用户当前决定：先记录阶段成果，后续优先优化LCD显示，暂不推进四舵机接线板、联合动作与机械制作。

建议按以下顺序细化，以下均为待做事项，不是已实现功能：

1. **先确定视觉稿**：基于240×280实屏规划眼睛大小、间距、位置、圆角和配色，以及状态栏、字幕的占用区域。先比较静态方案，再调整动画。
2. **改善眼睛形态**：从两个圆角矩形扩展出更有区别的开心、困倦、疑惑等眼形；保留待机、聆听、说话三种状态的辨识度。
3. **改善动作节奏**：调整眨眼的闭合与睁开曲线、随机间隔、视线停留和状态过渡，减少机械式周期运动。
4. **统一表情呈现**：目前仅部分情绪使用双眼，其他情绪回退原表情。评估如何统一风格，同时保留系统图标和异常提示。
5. **整理信息布局**：优化顶部状态与底部字幕的字号、边距、可读性，检查长文本和通知是否遮挡眼睛。
6. **实机验证性能**：边对话边观察闪烁、卡顿和音频；有证据后再调整刷新频率、重绘范围或SPI时钟。不能直接把名义20帧当作实测帧率。

下一次可以直接从“读取本文件和实际显示代码，设计LCD界面视觉稿”继续。保持现有屏幕接线与已验证的语音功能；若要做音量同步动画，需要另行设计音频数据接口，当前未实现。

```cpp
// 关闭新增双眼动画，继续使用已点亮的LCD和原来的小智表情。

```
