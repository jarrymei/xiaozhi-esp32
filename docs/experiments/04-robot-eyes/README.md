## 显示效果

本节到“已确认的实机结果”记录首版基线；眼形背景见“经典冷静精修实现”，对话动作见“自然灵动动作优化”，布局修正见“字幕恢复与启动提示”，当前待机动作见“空闲自动打瞌睡”，不要将历史方案或首版实测结论套用到新版。

黑色背景、青色圆角双眼，参考EMO的电子眼风格，使用LVGL图形绘制，不使用EMO原版素材。

| 设备状态 | 双眼表现 |
| --- | --- |
| 待机 | 正常睁眼，视线轻微左右移动 |
| 聆听 | 眼睛睁大，视线回到中央，颜色稍亮 |
| 说话 | 眼睛高度和位置轻微律动 |

首次眨眼约在界面建立1.8秒后，随后每隔约2.8～5.8秒再次眨眼；一次闭眼与睁眼约250毫秒。启动彩条覆盖期间，底下的眼睛动画也会继续计时，因此不一定能看到首次眨眼。

说话动画由设备状态驱动，**没有读取音量，也不是与语音逐字同步**。这版尚未实现眼神跟随摄像头或触摸。

云端下发的 `happy`、`laughing`、`loving` 会让眼睛变扁一些，`sad`、`sleepy` 会让眼睛半睁；`neutral` 恢复正常。其他情绪及系统图标仍调用原来的表情逻辑，下一次待机、聆听或说话状态可恢复双眼。

## 代码原理

`main/display/display.h` 增加默认不执行任何操作的 `SetInteractionState(DeviceState)` 接口。`main/application.cc` 在处理实际设备状态变化时调用它，其他显示器不需要修改。

本板的 `robot_eye_display.h` 继承已有LCD测试显示类，继续使用原来的状态栏、字幕和表情容器。每只眼睛是一个带圆角的LVGL矩形，通过改变高度模拟眨眼。状态切换时高度逐步接近目标值，减少突然跳变。

动画使用50毫秒周期的LVGL定时器，名义更新频率20次/秒。只创建一次对象，后续修改尺寸和位置，不在每帧创建图片、任务或对象，也不使用阻塞延时。实际刷新速度取决于SPI传输和系统负载，20次/秒不是实测保证。

外部状态和情绪更新使用显示锁；定时器回调运行在LVGL任务中。图片预览或系统图标隐藏双眼时跳过眼睛绘制。

## 拿麦克风唱歌动画

2026-11-02补充：用户确认现有设备已经能播放歌曲，希望播放时呈现拿麦克风唱歌的效果。当前仓库没有独立音乐播放器，云端音频共用播放通道。用户提供的实际日志显示：搜索时助手字幕包含 `% search_music...`，播放时包含 `% play_music...`，之后是歌名。此标记是本次自动触发依据，不能仅凭 `Speaking` 判定为音乐。

已增加的独立视觉能力：

- 保留经典冷静双眼，唱歌时略上移、轻微律动并交替笑眼；屏幕下部显示网格麦克风、小手握柄和浮动音符，不新增实体动作。
- 使用原50毫秒LVGL定时器，麦克风与音符层每100毫秒请求更新；装饰节奏不是音量或节拍同步。图层位于原脸部容器内，图片预览仍能整体隐藏，顶部状态栏和字幕实现不改。
- 新增本板专用MCP工具 `self.screen.set_singing_animation`，参数 `enabled` 为布尔值，`duration_seconds` 默认15秒，范围1～600秒。该工具只控制动画，不负责歌曲播放或停止，也不代表已确认音乐在播放。
- 可以说“演示拿麦克风唱歌的动画15秒”，或“关闭唱歌动画”，由云端调用工具。口头请求是否调用需看日志，不能保证模型每次执行。

- 自动触发：只识别助手字幕去除首尾空白后完整等于 `% play_music...` 的情况，开启动画；搜索标记、普通回复、歌名和歌词均不触发，原字幕照常显示。自动模式在退出 `Speaking` 时结束，或最长600秒后退出；MCP演示可在待机/说话继续，但进入聆听、配网、连接、升级等状态会退出。系统图标/未映射情绪优先。

```cpp
// 关闭新增双眼动画，继续使用已点亮的LCD和原来的小智表情。
#define BREAD_COMPACT_USE_ROBOT_EYES 0
```

重新编译烧录即可。`BREAD_COMPACT_USE_WAVESHARE_LCD` 继续保持1；它控制LCD与旧OLED的选择，不是眼睛动画开关。`DISPLAY_STARTUP_TEST_MS` 改为0可跳过启动彩条。
