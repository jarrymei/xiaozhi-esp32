# LCD视觉方案与交互规划

日期：2026-11-02。本文保留视觉方案比较和最初交互建议的历史背景，不作为当前界面规格。现已采用经典冷静青色双眼、自然灵动对话、空闲打瞌睡、居中联网提示和原单行字幕；用户已确认当前实屏效果可用，见[当前阶段记录](./README.md#当前阶段记录)。尚未实施的增强项见[后续待补齐功能](./README.md#后续待补齐功能)，用户已安排暂不开发。

## 四种眼睛方向

所有方案以240×280竖屏、黑底和无触摸操作为基准；均为原创绘制，不使用EMO原版素材。聊天中的预览按240×280设计像素绘制，浏览器字体、颜色、动画效果不等于实屏效果。

| 方案 | 眼睛与性格 | 信息布局 | 实现考虑 |
| --- | --- | --- | --- |
| 灵动电子眼 | 青色圆角大眼，无嘴；开心用弯月眼，疑惑用不对称眼形 | 待机弱化文字，对话才显示状态和字幕 | 推荐优先细化；可延续当前LVGL对象，弯月眼需补充绘制方式 |
| 软萌豆豆眼 | 杏黄色圆润豆形眼，小嘴辅助说话、微笑 | 顶部状态，眼睛略上移，底部双行字幕 | 更柔和；倾斜眼形和嘴形需要新增绘制，不是单纯改颜色 |
| 复古像素眼 | 薄荷色阶梯轮廓，无嘴 | 常驻简短状态，左对齐字幕 | 几何形态清晰，适合像素风；避免把字也做成难读像素字体 |
| 好奇瞳孔眼 | 淡蓝眼白和深色瞳孔，视线更明确 | 居中状态，下方独立字幕底色 | 瞳孔可在本地做巡视动画；不代表已有人脸跟踪或声源定位 |

建议先选眼形，再独立确定配色、字幕、状态栏密度，允许组合不同方案。不要只靠颜色区分聆听、思考、说话。

## 建议布局尺寸

以下为设计起点，不是当前代码已经采用的布局。坐标原点为可见屏幕左上角，不包含面板显存偏移。

- 顶部状态区：y=14～36，左右至少18像素安全边距；正常状态简短显示，通知替换此区域。
- 主脸区：约y=52～194，双眼中心参考x=72、168；正常眼形约62×66像素。眼形与间距可随风格调整。
- 字幕区：约y=216～266，优先16像素中文、两行、约12字/行；实际需按项目字体测量。长回复按语义分页或滚动，避免挤小字号。
- 顶部与底部保留圆角安全区域；预览边框仅表示屏幕，不代表机械外壳尺寸。
- 待机可隐藏非必要状态文字，但现有网络、静音、电池、通知能力必须保留。电池信息只在有可靠电源数据时显示，不虚构电量。
- 信息页可暂时缩小眼睛，为天气或计时让出空间；图片预览仍按既有路径显示。

## 交互规划

参考[LivingAI官方EMO介绍](https://living.ai/emo/)中的表情反馈、天气展示、闹钟和生日互动；以下是本项目建议，不能当作EMO功能的完整复刻清单，也不能视为本项目已实现。

| 优先级 | 触发 | 建议屏幕反馈 | 当前基础与新增工作 |
| --- | --- | --- | --- |
| 首批 | 待机 | 随机眨眼、短暂侧看、停留后回正 | 已有基础动画，改进眼形与动作节奏 |
| 首批 | 唤醒、进入聆听 | 睁大眼睛并回正，出现“在听你说”和小型聆听标记 | 已有聆听状态；标记是状态动画，非真实音量 |
| 首批 | 提交语音后等待回复 | 轻微抬眼、三个点，短提示“想一想” | 待核对实际状态与消息时序，不能把任何网络连接状态直接当思考 |
| 首批 | 收到回复、说话 | 小幅表情律动、双行回复字幕 | 已有状态与字幕；音量同步需另建音频数据接口 |
| 首批 | 云端情绪 | 开心弯月眼、疑惑高低眼、困倦半闭眼、委屈斜眼睑 | 已有部分情绪映射；完整情绪名称需按实际云端协议核对 |
| 首批 | 断网、连接失败、静音、系统通知 | 保留明确文字和系统图标，恢复后回脸部 | 复用现有通知能力，系统错误优先于装饰动画 |
| 后续 | 语音询问天气 | 缩小眼睛，展示天气和温度，再恢复脸部 | 需要可用天气数据源、地点与消息接口；预览23°为示例 |
| 后续 | 语音设置倒计时 | 缩小眼睛，显示剩余时间，到时惊喜表情与提示 | 需新增本地计时与取消逻辑；预览24:59为示例 |
| 后续 | 生日或节日 | 祝福文字、短时彩纸或蛋糕动画 | 需设置日期、可靠时间和触发策略，不能凭空知道生日 |
| 后续 | 语音说“开心一点”“晚安” | 切表情或进入低亮度休息脸，唤醒后恢复 | 需明确命令入口、亮度恢复与对话退出规则 |
| 可选 | 猜拳、掷骰子、猜数字 | 简单图案、倒数与输赢表情 | 可用语音作输入；需定义游戏状态与超时退出 |
| 暂缓 | 摸头、拿起、倾斜、看向人 | 对应情绪或跟随反馈 | 当前无触摸LCD；需独立传感器、摄像头或其他已确认输入，不能仅靠屏幕实现 |

## 动画与状态原则

- 单次眨眼可先试闭合90毫秒、停留50毫秒、睁开160毫秒，再实屏调整；现有50毫秒定时器会限制时间粒度，预览不是实机刷新率测试。
- 视线采用“移动—停留—回正”，避免持续正弦摆动；聆听时减少巡视，突出注意力。
- 情绪与交互状态分开：聆听或说话时仍可保持开心，但系统告警与图片预览优先。情绪需有退出条件，避免一直残留困倦脸。
- 状态转换可先试150～250毫秒平滑过渡。只在交互需要时运动，不让字幕和整屏持续跳动。
- 对话结束后清理过期字幕，恢复脸部；通知与长字幕不能盖住眼睛。图片预览结束后恢复正确状态。
- 天气、计时等信息页保留现有通知入口；对话唤醒可切回聆听，事件完成后按明确规则恢复。

## 下一步与验证边界

先由用户选择眼形、字幕布局和配色，再改板级显示实现。首批建议只做统一眼形、六种基础表情、状态过渡和字幕布局，后续再加天气、计时等独立功能。

设计阶段仅完成规划；后续已按“经典冷静”改板级显示实现，保留现有功能及回退开关。实屏仍需检查圆角裁切、长字幕、图片预览、通知、多轮对话和音频稳定性，不能以聊天预览替代实物验收。
