# 微雪1.69寸LCD首次点亮与小智界面适配

记录日期：2026-11-02。开发环境：Windows、PowerShell、ESP-IDF v5.5.6，小智v2.2.4，板型继续为Bread Compact WiFi，主控ESP32-S3 N16R8。

## 1. 本次使用的屏幕和目标

微雪`1.69inch LCD Module`独立无触摸模块，ST7789V2驱动、SPI接口、240×280像素。不是带ESP32的整板，也不是Touch LCD Module。

第一步先竖屏点亮，观察红绿蓝色条、四边白框和上下方向，再进入原小智界面。软件编译通过只能说明代码可构建，不能证明实物已经点亮。

厂商资料：[微雪官方说明](https://www.waveshare.com/wiki/1.69inch_LCD_Module)。其要求供电与控制逻辑电压一致，本接法统一使用3.3V；新购舵机5V电源不用接入此次显示实验。

## 2. 接线表

**先拔掉开发板USB，拆除原OLED及此前LED、舵机实验支路；麦克风、功放和扬声器保持原接线。** 不要拆掉其他模块共享的电源和GND。

| 屏幕接口丝印 | 接ESP32-S3 | 原理 |
|---|---|---|
| VCC | 3V3 | 模块供电，匹配ESP32的3.3V信号 |
| GND | GND | 共同电压参考 |
| DIN | GPIO10 | SPI MOSI，从ESP32向屏幕发送指令或像素 |
| CLK | GPIO9 | SPI时钟 |
| CS | GPIO12 | 低电平选中屏幕 |
| DC | GPIO11 | 区分指令和像素数据 |
| RST | GPIO21 | 硬件复位 |
| BL | GPIO1 | 背光控制输入，高电平有效，程序输出PWM |

```text
电脑USB ───────────── ESP32-S3开发板
                         3V3 ───── VCC
                         GND ───── GND
                      GPIO10 ───── DIN
                       GPIO9 ───── CLK
                      GPIO12 ───── CS       微雪1.69寸LCD
                      GPIO11 ───── DC
                      GPIO21 ───── RST
                       GPIO1 ───── BL
```

- 按屏幕/线束的真实接口标记接线，不凭导线颜色或连接器方向猜线序。GPIO编号不是物理第几个针脚。
- 使用尽量短的杜邦线，插头完全插稳，面包板电源轨如有中间断点需确认连通。
- 原OLED使用GPIO41、42，新屏不接它们。GPIO4、5、6继续接麦克风，GPIO7、15、16继续接功放。
- GPIO17舵机和GPIO18灯光的代码仍保留，拆掉实物不会与这八根LCD接线冲突。
- BL是模块的背光控制接口，不是让GPIO直接驱动裸背光灯的接法。不要将已接GPIO1的BL同时硬连3V3。

## 3. 当前代码如何选择屏幕

编辑[`config.h`](../../../main/boards/bread-compact-wifi/config.h)：

```cpp
// 1：本次微雪彩屏；0：恢复原SSD1306/SH1106 OLED路径。
#define BREAD_COMPACT_USE_WAVESHARE_LCD 1

// 启动显示测试画面的时长；实物确认后改为0可跳过测试。
#define DISPLAY_STARTUP_TEST_MS 5000
```

这次使用板级开关，不改小智板型，也不需要升级工程或重新配网。`sdkconfig`里的SSD1306选项仍保留，彩屏路径下不参与显示初始化；开关改成0并按旧接线连接OLED后会重新使用它。

| 实现位置 | 本次改变 |
|---|---|
| [`config.h`](../../../main/boards/bread-compact-wifi/config.h) | GPIO分配、彩屏/OLED开关、分辨率、20行偏移及测试时长 |
| [`compact_wifi_board.cc`](../../../main/boards/bread-compact-wifi/compact_wifi_board.cc) | 增加SPI3总线与ST7789初始化，使用现有公共PWM背光类 |
| [`waveshare_lcd_test_display.h`](../../../main/boards/bread-compact-wifi/waveshare_lcd_test_display.h) | 继承现有SpiLcdDisplay，启动时添加测试覆盖层，定时自动移除 |

公共音频代码、MCP日志、灯光与舵机控制器不作更改。原BOOT提示回调也保留。首次修改前的两个板级文件保存于[`before-lcd`](./before-lcd/)，它们仅供对照，未来有新修改后不要直接整文件覆盖恢复。

## 4. 显示和背光参数

| 参数 | 初始值 |
|---|---|
| SPI总线 | SPI3_HOST，DMA自动分配；不接MISO |
| SPI模式和时钟 | Mode 0，10MHz，优先适应首次杜邦线调试 |
| 像素格式 | RGB565，16位；LVGL公共显示实现负责像素字节交换 |
| 可见分辨率 | 宽240，高280，竖屏 |
| 显存偏移 | X=0、Y=20，仅通过面板`set_gap`设置一次 |
| 颜色顺序 | RGB |
| 反色设置 | 开启，沿用此类IPS ST7789的初始配置，仍需实物确认 |
| 镜像/XY交换 | 均关闭 |
| 背光GPIO | GPIO1，高电平有效 |
| 背光LEDC | 定时器0、通道0，25kHz、10位 |
| 保留LED实验 | 定时器2、通道2、5kHz |
| 保留单颗舵机实验 | 定时器3、通道3、50Hz |

ST7789的显存有320行，而该屏可见区域只有280行，因此需要按该面板窗口添加偏移。偏移只加一次：硬件驱动设20行，传给SpiLcdDisplay的LVGL偏移为0，避免重复偏移造成裁切。

背光初始化从关闭开始，面板初始化后恢复显示设置中的亮度。没有保存亮度时公共背光类默认目标为75%，它会逐步渐亮。GPIO1是控制PWM，不是彩屏SPI时钟。

这次没有改变字体打包、语音资源或编译优化；当前`CONFIG_COMPILER_OPTIMIZATION_SIZE=y`，仍为`-Os`，并未改为`-Og`。

## 5. 烧录与实物验收

1. 断电按上表接线；首次测试不接舵机外部电源。
2. 在ESP-IDF v5.5.6环境执行`idf.py build`，或使用VS Code原来的编译按钮。
3. 使用你已有的烧录流程烧录新的固件，然后复位并打开日志。串口号以当次实际端口为准。
4. 正常预期：背光亮起，约5秒显示左红、中绿、右蓝三条色条；各条分别标R、G、B，并显示TOP和BOTTOM标签及内缩白框。
5. 约5秒后测试覆盖层移除，出现原小智状态、表情和对话文字。网络初始化与测试层计时并行，不需要联网成功才能看测试条。
6. 检查方向、白框四边、颜色和文字；然后验证麦克风、功放及BOOT按键仍正常。

测试白框距离边缘6像素，避开屏幕圆角，不应被裁掉一整边。如果想重复看测试图，复位开发板即可；无需新注册MCP工具。

对应日志：

```text
[LCD INIT]       开始设置微雪面板，打印分辨率和SPI时钟
[LCD PINS]       打印CLK、DIN、CS、DC、RST、BL的GPIO
[LCD READY]      驱动API调用成功，不代表屏幕有响应
[LCD TEST]       测试覆盖层已创建
[LCD TEST DONE]  测试层移除，露出小智界面
```

本屏未连接数据读回线，初始化不能自动判断LCD是否插好。看到`LCD READY`但屏幕仍黑，应按接线排查，不把日志成功当作实物验收。

## 6. 常见现象

| 现象 | 优先检查 |
|---|---|
| 屏幕完全黑 | 3V3/GND是否到模块、BL是否接GPIO1、接插件是否插牢、日志是否启动到LCD |
| 背光亮但无图像或白屏 | DIN/CLK/CS/DC/RST线序、是否真为独立ST7789V2模块、程序是否为新编译固件 |
| 上下缺边、图像偏移 | Y偏移是否为20、分辨率是否240×280；不在LVGL重复加偏移 |
| 红蓝条对调 | 先核对测试条R/G/B；必要时将`DISPLAY_RGB_ORDER`改为BGR并重新编译 |
| 颜色整体异常 | 区分RGB顺序、像素字节序和反色；不要同时乱改多个参数，先保留公共RGB565字节交换 |
| 图片倒置或镜像 | 拍下TOP/BOTTOM及白框的位置，再调整对应镜像参数；横屏还涉及宽高与偏移，首轮先保持竖屏 |
| 花屏、偶发线条 | 检查接触、缩短杜邦线，必要时将SPI时钟从10MHz降到5MHz |
| 一开始色条，后变成界面 | 正常，5秒测试结束 |
| 编译成功但未观察到色条 | 确认实际烧录的是本次固件，复位后立即观察屏幕；检查测试时长不是0 |
